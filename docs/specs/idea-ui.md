# 灵感台界面规格（阶段 1）

- 日期：2026-10-10（v2 同日：详情改为左右分栏 + 多 tab，新增第 9、10 节）
- 来源：原灵感台界面（`bluemanta-workbench/modules/inspiration_desk/ui/`），由 Claude Code 提炼；实现者以本文为准，不需要读原代码。
- 原则：**交互沿用原灵感台，视觉跟随 dsh**（只用 `--dsw-alias-*` 主题变量，浅色 / 深色都要正常，列表行、间距、字号参照 dsh 自带的「插件」管理页）。
- 内容线相关的部分（选题、发布台、账号、复盘回顾，以及清单里的"已立项""做成内容""加入已有选题""未立项"筛选、多选立项）都在阶段 2，本文不含。

## 1. 入口与导航

- dsh 左侧栏只有**一个入口「灵感台」**（沿用现有面板 id `bluemanta.ideas`，图标沿用灯泡）。
- 主区域左侧是灵感台自己的二级菜单，约 160px 宽，顺序：**灵感清单**（默认）、**数据统计**、**回收站**。阶段 2 会在中间插入选题、发布台、账号、复盘回顾。
- 主区域宽度 ≤ 820px 时，二级菜单变成顶部一行可横向滚动的标签。
- 二级菜单里不放"新增"。

## 2. 灵感清单

### 顶部

- 标题「灵感清单」，右上角按钮「新增」，打开新增抽屉（第 4 节）。
- 搜索框，占位文字「搜索标题、正文、原文或分类」，有内容时显示清空按钮。搜索调用已有的 `GET /api/bluemanta/cards?q=`。
- 筛选，两组单选按钮，与搜索叠加生效：
  - 范围：全部 / 收藏；
  - 分类：全部 / 产品想法 / 学习备忘 / 工作事务 / 生活随想 / 其他。
- 从数据统计点了某一天进来时，显示一个可清除的标签「某月某日」，列表只显示当天记下的灵感。

### 列表

- 按创建时间倒序，新的在上。
- 每条卡片：
  - 标题（为空时显示「未命名灵感」），后面跟分类标签；有追记时显示追记条数标记；
  - 摘要：搜索时显示命中位置的摘录，否则显示正文开头约 120 字；
  - 元信息：相对时间（刚刚 / N 分钟前 / N 小时前 / 昨天 / 具体日期），修改过时加「已改写」，搜索时加「匹配标题 / 正文 / 原文 / 分类」；
  - 有图时右侧显示第一张图的缩略图，点击打开大图浏览；
  - 最右侧收藏星标按钮，点击直接收藏 / 取消收藏，不打开详情。
- 点卡片其余区域在右侧详情区打开这条灵感（第 9 节）。
- 空状态：
  - 没有任何灵感：「还没有记下灵感。点右上角「新增」，可以只写文字、只贴图，或两者一起记下。」
  - 有灵感但筛选无结果：「没有匹配的灵感。」
- 读取中显示「正在读取灵感…」。

## 3. 灵感详情

显示位置见第 9 节（宽屏为右侧详情区的一个 tab，窄屏为整页）。以下为详情内容本身。

- 顶部：收藏星标、关闭按钮。
- 只读状态：标题、分类、正文、图片缩略图（点击看大图）。
- **原文：** 正文下方直接显示「原文」小标题和只读的原始输入，不折叠、不需要点击（2026-10-11 用户决定）。以下情况不显示原文区块：原文与正文相同，或正文已包含原文全文（比较时忽略首尾空白和连续空白的差异）；原文为历史数据（`legacy`）或为空。
- **编辑：** 点「编辑」进入编辑态，可改标题、正文、分类，可增删图片（最多 4 张）；「保存」「取消」。
  - 有未保存的修改时，关闭该 tab、返回列表或切换二级菜单页面要二次确认。
  - 保存失败时保留草稿并显示原因；版本冲突时提示「这条灵感已在别处更新」，保留你的草稿，并提供"重新载入"。
- **追记（原灵感台叫"延展"）：** 「延展」区块，按时间正序显示每条追记及时间；每条可删除（需确认）。下方输入框，占位「写下理解、续写或补充…」，按钮「追加延展」，空内容时禁用。
- 底部左侧「移入回收站」（不需要确认，可在回收站恢复）。

## 4. 新增灵感

显示位置见第 9 节（宽屏为右侧详情区的「新增灵感」tab，窄屏为整页）。

- 标题「新增灵感」。
- 标题输入框，占位「一句话概括…」；正文输入框，占位「把闪过的念头写下来…」。
- 图片：可点选文件、拖入、粘贴截图，最多 4 张，可单独移除；上传中显示进度，失败可重试。
- 「取消」「保存」。标题、正文、图片都为空时「保存」禁用。
- 保存成功后，「新增灵感」tab 变为这条新灵感的详情 tab，新灵感出现在列表顶部；失败时保留输入并显示原因。
- 分类不用选，由 core 自动分类；之后可在详情里修改。

## 5. 数据统计

- 标题「数据统计」，一句说明「灵感频率按记下日期本地计数，上海时区。」
- 顶部几个轻量汇总数字：全部、本周、本月、收藏。
- **频率热力图：** 最近约 26 周，每格一天，按 `Asia/Shanghai` 自然日统计 `createdAt` 条数，颜色深浅表示数量（用主题强调色的不同透明度）。宽度铺满内容区，单元格随容器变宽；过窄时减少列数但仍铺满。
  - 悬停显示「日期 · N 条」。
  - 点击某天：回到灵感清单，并按当天筛选（第 2 节的日期标签）。
- 没有灵感时显示「还没有记下灵感，热力图先空着。」
- 在前端计算，不新增数据表。

## 6. 回收站

- 标题「回收站」，列出回收站里的灵感（`trash=1`），按移入时间倒序。
- 每条：标题、移入时间；操作「恢复」「彻底删除」。
- 彻底删除前确认：「彻底删除后无法恢复。确定删除这条灵感？图片和延展会一并移除。」
- 空状态：「回收站是空的。」

## 7. 接口（宿主端）

全部用 `ctx.connection.fetch.register` 注册，复用 dsh 鉴权；处理函数写成与 dsh 解耦的纯函数，便于测试。

- **写命令** `POST /api/bluemanta/commands`，请求体 `{ command, input }`：
  - 白名单：`card.create`、`card.update`、`card.delete`、`card.restore`、`card.purge`、`card.setStar`、`card.addExtension`、`card.deleteExtension`；其他命令 400。
  - 宿主端强制写入 `source: { kind: 'human', name: 'desktop' }`，忽略请求里的 `source`（界面上的操作都是人做的）。
  - `requestId` 由前端生成（UUID），失败重试时沿用同一个，保证不会重复写入。
  - 返回 core 的结果；`invalid_input` → 400，`not_found` → 404，`version_conflict` / `duplicate_request_mismatch` → 409，`forbidden_source` → 403，均带 `message`。
- **上传图片** `POST /api/bluemanta/attachments`（`requestBody: 'streaming'`）：
  - 单张 ≤ 8 MB；按文件头识别真实类型，只接受 jpeg / png / gif / webp；读取宽高（≤ 16384 像素）；计算 sha256。不引入新依赖，自行解析这四种格式的文件头。
  - 保存到 `<数据目录>/media/<附件 id>.<扩展名>`（与 T4 导入的目录约定一致），在 core 中新增 `attachment.create` 命令建记录，返回附件元数据；之后由 `card.create` / `card.update` 的 `attachmentIds` 绑定。
  - 上传后 24 小时仍未被任何卡片引用的附件，在插件启动时清理（文件与记录）。
- **读取图片** `GET /api/bluemanta/attachment?id=<附件 id>`：返回文件，带正确的 `content-type` 和缓存头。（dsh 只支持精确路径注册，所以 id 放在查询参数里。）
- **彻底删除卡片时**删除其附件文件（core 已返回附件 id 列表）。
- 规格 `idea-rules.md` 第 8 节的附件元数据校验在本任务实现。

## 8. 前端约束

- 沿用 `client.js` 的模块加载格式与 dsh 插件开发指南：不 import 任何 `@deepseek-ai/dsh-client-*` 包，只用主题变量，组件内自管样式。
- 图片用 `<img src="api/bluemanta/attachment?id=…">` 相对路径加载。
- 确认框、大图浏览等浮层放在面板自己的 DOM 内，不往 `document.body` 追加节点；浮层必须相对**不滚动的外层容器**定位，覆盖当前可见区域，不能随内容滚动（v1 的抽屉在列表滚动后停留在内容顶部，即此问题）。
- 所有界面文字为中文。

## 9. 布局：列表与详情左右分栏（v2）

替代 v1 的详情抽屉和新增抽屉。

### 宽屏（主区域足够放下"二级菜单 + 列表 + 详情"时）

```
二级菜单 │ 列表区（可拖动调宽）│ 详情区：tab 条 + 当前 tab 内容
```

- **列表区**：第 2 节的顶部与列表，独立滚动。
- **拖动调宽**：列表区与详情区之间有一条分隔线，可拖动调整列表宽度。默认 380px，最小 280px，最大为主区域宽度的 60%；双击分隔线恢复默认；宽度记在本机（`localStorage`，只存界面偏好，不存业务数据）。分隔线获得焦点时可用左右方向键微调。
- **详情区 tab 条**：
  - 点列表中的灵感：已打开则切换到它的 tab，未打开则新开一个 tab 并切换过去；当前打开的 tab 在列表中高亮。
  - 「新增」在详情区开一个「新增灵感」tab（同一时间只有一个）。
  - 每个 tab 显示标题（过长截断）和关闭按钮；有未保存修改时标题旁显示圆点，关闭前二次确认。
  - 最多 8 个 tab；超出时关闭最早打开且没有未保存修改的 tab；都有未保存修改时不再新开，并提示。
  - 灵感被移入回收站或彻底删除后，它的 tab 自动关闭。
  - 没有 tab 时，详情区显示「选一条灵感查看」。
  - tab 样式参照 dsh 右侧栏的 tab 条，只用主题变量；tab 状态保存在内存中，重启后不恢复。
- 详情区内容独立滚动，不影响列表滚动位置。

### 窄屏（放不下三栏时）

- 只显示列表。点一条灵感或「新增」进入整页详情，左上角「← 返回」回到列表，并恢复原来的滚动位置。
- 不使用蒙版和抽屉。

## 10. 在对话旁打开灵感（dsh 右侧栏）

dsh 原生的右侧栏绑定在对话上：主区域显示对话时才有。本节让用户在和 agent 对话时，在右侧栏里查看灵感。

- **注册右侧栏 tab 类型**「灵感」（`ctx.sidebarRightTabs.register`，页类型，按 kind 打开，参数为灵感 id），正文复用第 3 节的详情组件（可查看、编辑、收藏、追记，规则同灵感台；写入同样以"人"为来源）。
- **右侧栏「开始」页增加入口**「灵感台」：打开一个右侧栏 tab，里面是精简列表（搜索 + 列表），点一条在右侧栏打开该灵感的 tab。
- **对话里的工具卡片**：agent 调用 `bluemanta_idea_capture` / `bluemanta_idea_search` / `bluemanta_idea_get` 后，对话中显示自定义卡片（`tool.call.toolview`）：
  - capture：「已记录灵感：标题 · 分类」+「打开」按钮；
  - search：命中列表（标题、分类、日期），每条可点「打开」；
  - get：标题 + 摘要 +「打开」。
  - 「打开」调用 `ctx.sidebarRight.openTab` 在当前对话的右侧栏打开该灵感。
- 主区域显示灵感台等全局页面时没有右侧栏，相关入口不显示，不能报错。
