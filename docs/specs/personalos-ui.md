## 1. PersonalOS 的格式（解析依据）

PersonalOS 的格式由它自己的蓝图定义（不在本仓库）。下面是解析需要的全部规则。**真实文件会偏离模板，解析必须宽容**：认得的结构化，认不出的保留原文 Markdown，任何一处解析失败都不能让整页报错。

### 1.1 目录

```text
PersonalOS/
├── AGENTS.md            入口：「关于我」、路由表、读写规则
├── CLAUDE.md            只有一行 @AGENTS.md（忽略）
├── 收件箱.md
├── 我/                  状态.md、资料登记.md
├── 领域/<领域名>/        状态.md、资料登记.md（可能没有）、知识.md 或 知识/（可能没有）、事项/（可能没有）
├── 协议/*.md
├── 日志/YYYY-MM.md
├── 蓝图/*.md
├── .git                 一行指针文件（忽略）
├── .gitdata.nosync/     Git 仓库数据（忽略，迭代 2 只读调用 git）
└── .claude/、.DS_Store   忽略
```

- 以 `.` 开头的文件和目录一律不列出、不索引、不允许经接口读取。
- iCloud 未下载的文件在磁盘上是 `.<原名>.icloud` 占位文件。遇到时该文件标为「尚未从 iCloud 下载」，不当成空文件或不存在。

### 1.2 路由表（`AGENTS.md`）

- 第一张表头包含「领域」「路径」的 Markdown 表格就是路由表。列：领域、路径、别名与关键词、典型问题。
- 路径单元格形如 `` `我/` `` 或 `` `领域/数云工作/` ``，去掉反引号和末尾 `/`。
- 别名与关键词、典型问题按 `、` `；` `;` `，` 切分并去空白。
- **领域列表以路由表为准**，顺序就是表格行序。磁盘上有、路由表里没有的领域目录也要列出，标「未登记」，排在最后。路由表里有、磁盘上没有的标「目录不存在」。
- 领域 id 用领域名（如 `数云工作`），URL 中做 `encodeURIComponent`。
- 「关于我」：`## 关于我` 下的正文，原样保留为 Markdown。

### 1.3 `状态.md`

```markdown
# 创业 · 状态
更新于：2026-11-15

## 现状
## 未结事项
## 近期变化
## 去哪查
```

- 「更新于」：匹配 `更新于[：:]\s*(\d{4}-\d{2}-\d{2})`，取文件前 10 行中第一个。没有则为空。
- 按 `## ` 切节，标题去掉首尾空白后识别。领域文件的四节：现状、未结事项、近期变化、去哪查。`我/状态.md` 的七节：我是谁、长期方向与价值取向、当前重点、现实约束、和 AI 协作的偏好、未结事项、去哪查。其他标题当作普通节，按出现顺序原样渲染。
- 节内允许出现 `###` 小节、加粗段落、表格等任何 Markdown，原样保留。
- **「去哪查」**：第一个 `###` 之前的内容是链接列表；每个 `### 标题` 到下一个 `###` 或文件结尾是一张**挂接卡片**（标题 + Markdown 正文）。
- **近期变化**：每行 `- YYYY-MM-DD 内容` 解析为一条（日期 + 文本），其他行原样保留。
- **只有「暂无」或「待补充」的节**：标为空节，界面显示这两个字的灰色说明，不显示成内容。

### 1.4 未结事项（待办）

只在 `状态.md` 的「未结事项」节里解析，含 `我/状态.md`。

| 写法 | 含义 |
|---|---|
| `- [ ] 事项 @due(2026-11-20)` | 有截止日期 |
| `- [ ] 事项 @wait(谁)` | 等别人，可同时有 `@due`（表示跟进日期） |
| `- [ ] 事项 @every(1y) @due(2027-03-01)` | 周期性；完成后不打勾，`@due` 改成下一次 |
| `- [ ] 事项` | 无日期 |
| `- [x] 事项 2026-11-21` | 已完成，行尾可选完成日期 |

- 行匹配：`^\s*[-*] \[( |x|X)\]\s+(.*)$`。
- 标签：`@due(YYYY-MM-DD)`、`@wait(任意文本)`、`@every(\d+[wmy])`。其他 `@名字(…)` 保留为未知标签原样显示。标签从文本里去掉后，剩下的去空白即事项文本。文本里的 Markdown 链接保留。
- `@due` 日期不合法时：该事项归为无日期，并带一条警告。
- 每条事项记下所在文件和**行号**（迭代 3 写入要用）。
- 「等了多久」：格式里没有等待起始日期，一律显示「未记录」，**不推算**。

### 1.5 今天的分组

「今天」= 服务所在时区的当天日期；测试和走查用环境变量 `BLUEMANTA_TODAY=YYYY-MM-DD` 固定。只看未完成事项，每条事项只出现在一组：

1. **已逾期**：`@due` < 今天。
2. **今天到期**：`@due` = 今天。
3. **未来 7 天**：今天 < `@due` ≤ 今天 + 7。
4. **等待中**：有 `@wait`，且不在上面三组。
5. **无日期**：没有 `@due` 也没有 `@wait`。页面只显示前 3 条（按领域顺序、再按文件内顺序），注明「还有 N 条」。
6. **更晚**：`@due` > 今天 + 7。只显示条数，可展开。

组内按 `@due` 升序，同日按领域顺序。带 `@wait` 的事项在前三组里加「等待：谁」标记；带 `@every` 的加「每 1w」之类标记。

**过期领域**：「更新于」距今天超过 14 天，或没有「更新于」。

### 1.6 `资料登记.md`

- 表头含「主题」「资料」「位置」「用途」「状态」的表格。一个文件可能有多张表，都解析。
- 位置单元格分三类：
  - **本机路径**：反引号里以 `~/` 或 `/` 开头。服务端只用 `stat` 判断是否存在（不读内容），返回时 home 缩写成 `~`；
  - **链接**：Markdown 链接 `[文本](https://…)`；
  - **其他**：原样显示（如 MCP 调用说明）。
- 状态只有 `引用`、`已入库`，其他值原样显示。

### 1.7 收件箱、日志

- `收件箱.md`：每行 `- YYYY-MM-DD 内容` 是一条；文件头部的说明文字不算条目。
- `日志/YYYY-MM.md`：
  - 条目：`- YYYY-MM-DD [领域] 内容`，`[领域]` 可省略；
  - `## 标题` 小节（阶段交付说明、验收记录）：标题 + 正文 Markdown，挂在小节标题里的日期上（取不到就挂在月份上）；`###` 小节同样处理；
  - **条目和小节的边界**（2026-11-21 验收补充）：真实日志是追加写的，小节后面会继续出现条目，条目也会夹在小节的列表中间。规则：不缩进的 `- YYYY-MM-DD …` 行**一律是条目**，不管它出现在哪个小节下面；它不计入小节正文。小节正文是从标题到下一个 `##`/`###` 标题之间、去掉这些条目行后的其余内容（首尾空行去掉）。去掉条目后正文为空的小节仍保留标题。
  - **条目的方括号标签**：`[…]` 里的文字和路由表领域名（含「我」）一致时才是领域；不一致的（如 `[蓝图]`、`[阶段 3]`）`domain` 为空，原文放进 `tag` 字段，界面按普通灰色标签显示。领域筛选只按 `domain` 过滤，另加一个「未归领域」选项，包含 `domain` 为空的条目和小节。
  - 按日期倒序合并所有月份。

### 1.8 事项与知识（用到时才有）

- 事项：`领域/<名>/事项/*.md`，或 `事项/<名>/` 目录（目录内的 `.md` 都算该事项的文件，以与目录同名的或 `README.md` 为入口）。
- 知识：`领域/<名>/知识.md`，或 `知识/*.md`；`我/` 下同理。
- 都没有时界面不显示对应区块。

## 3. 今天页（默认）

自上而下：

1. **当前重点条**：`我/状态.md`「当前重点」节的条目（最多 3 条），单行省略，点击打开 `我` 的详情。没有就不显示。
2. **概况行**（32px）：今天日期（`2026-11-21 周六`）、「N 件到期或逾期」「M 件等待中」「收件箱 K 条未分拣」。（「数据读取于」迭代 2 起移到页头，见 12.6。）
3. **事项分组**，顺序同 1.5：已逾期（标题用警示色）、今天到期、未来 7 天、等待中、无日期、更晚（折叠）。空组不显示；全部为空时显示「没有到期的事」和下一件 `@due` 事项的日期。
   - 行 34px：复选框位置显示**只读的空心圆**（迭代 3 才能勾选）、事项文本（链接可点，新窗口）、标记（等待、周期）、日期（已逾期写「逾期 N 天」，未来写「周一 11-23」）、领域标签。
   - 点行或 ↵：右侧打开该领域详情并滚动到该事项。J / K 移动。
4. **需要留意**：过期领域列表（领域名 + 「N 天未更新」或「没有更新日期」），点击打开领域详情。
5. **收件箱**：未分拣条目（日期 + 内容），只读；顶部一行说明「晨间简报时由 agent 分拣」。0 条时不显示。

## 4. 领域页

### 4.1 领域卡片网格

- 按路由表顺序排列，`我` 在最前。卡片最小宽 240px，自适应列数；720 宽时单列。
- 卡片内容：领域名；「更新于 YYYY-MM-DD」（过期时用警示色并写「N 天前」）；未结事项数（其中逾期数用警示色）；「待补充」出现次数（为 0 不显示）；近期变化的第一条（单行省略）。
- 「未登记」「目录不存在」的领域在卡片上加小标。
- 点击卡片或 ↵：右侧打开领域详情。J / K / H / L 在网格里移动。

### 4.2 领域详情（右侧卡片，420px，可拖 320–720）

1. **标题**：领域名；元信息行：更新于、文件路径（库内相对路径，「复制路径」）、「只读」标。
2. **页签**：
   - **状态**：按文件顺序渲染各节。「未结事项」用 3 节的事项行（只读）；「近期变化」用日期 + 文本的列表；「去哪查」先渲染链接列表，再把每张挂接卡片渲染成带边框的块，块标题后加「外部 · 只读」小标。
   - **资料**：本领域资料登记表（同第 5 节的列），没有资料登记时显示「这个领域还没有资料登记」。
   - **事项**、**知识**：有文件才显示这两个页签。列出文件，点开进阅读器。
   - **文件**：本领域目录下所有 Markdown 文件，点开进阅读器。
3. 正文中的「待补充」「（推断）」「未核验」用 `--bm-mark` 背景高亮，帮助发现缺口。
4. 相对链接（如 `../内容创作/状态.md`）：指向其他领域的 `状态.md` 时打开那个领域详情；指向其他 `.md` 时进阅读器；`#锚点` 链接滚动到对应标题。

### 4.3 阅读器

沿用 v1 阅读器。面包屑改为「PersonalOS / 领域 / 文件名」。PersonalOS 根目录的文件（`AGENTS.md`、`协议/*`、`蓝图/*`）在领域网格下方的一行「关于 PersonalOS：入口说明 · 协议 · 蓝图」里打开。

## 8. 接口（迭代 1）

全部需要本机口令，校验同现有接口。返回的路径一律是 PersonalOS 库内相对路径；库根目录只用于显示，home 缩写成 `~`。

| 方法与路径 | 返回 |
|---|---|
| `GET /api/v1/personalos` | 概览：`root`（`~` 缩写）、`exists`、`today`、`about`（关于我 Markdown）、`focus`（当前重点条目）、`domains`（领域摘要数组：id、name、path、registered、exists、updatedAt、stale、staleDays、openCount、overdueCount、gapCount、latestChange）、`inbox`（条数）、`warnings` |
| `GET /api/v1/personalos/today` | 第 1.5 节的分组：`overdue`、`dueToday`、`next7`、`waiting`、`undated`（`items` 前 3 条 + `total`）、`later`（`count` + `items`）、`staleDomains`、`inbox`（条目数组）、`today` |
| `GET /api/v1/personalos/domains/:id` | 领域详情：摘要字段 + `file`（状态文件相对路径）+ `sections`（`title`、`kind`、`markdown`、`empty`）+ `todos` + `changes` + `links`（去哪查的链接部分 Markdown）+ `mounts`（`title`、`markdown`）+ `registry` + `matters` + `knowledge` + `files` |
| `GET /api/v1/personalos/registry` | 全部资料登记行：`domain`、`topic`、`title`、`location`（`kind: local/link/other`、`display`、`exists?`、`url?`）、`purpose`、`status`、`source`（所在文件） |
| `GET /api/v1/personalos/log?domain=&before=YYYY-MM-DD&days=30` | 日志条目和小节，按日期倒序；`hasMore` |
| `GET /api/v1/personalos/files/*` | 同 v1 文件接口的形状（Markdown 内容或文件元信息） |

- 待办对象：`id`（文件路径 + 行号的稳定串）、`domain`、`file`、`line`、`text`、`done`、`doneAt`、`due`、`wait`、`every`、`tags`（未知标签）、`bucket`。
- PersonalOS 目录不存在：概览返回 `exists: false`，其余接口返回 404 `library_missing`；网页整区说明「没有找到 PersonalOS」，写出路径（`~` 缩写）和「在启动服务前设置 BLUEMANTA_KNOWLEDGE_HOME」。
- 路径越界、以 `.` 开头的路径：400 `invalid_path`。
- 文件读取：每个请求现读文件（PersonalOS 只有几十个小文件）；不缓存跨请求的解析结果。迭代 2 加了监听，仍不加解析缓存，见 12.6。

## 9. 虚构 fixture

放在 `packages/knowledge/fixtures/home/Documents/PersonalOS/`，和现有知识库 fixture 同一个 home，`BLUEMANTA_KNOWLEDGE_HOME` 指过去即可。**全部内容虚构，不得复制或改写真实 PersonalOS 的任何文字。** 用一个虚构人物（如「林舟」，产品经理），领域名可以和真实结构一致（我、工作、副业、写作、技术、家庭、健康、财务、生活事务），内容自编。

必须覆盖（以 `BLUEMANTA_TODAY=2026-11-21` 为基准写日期）：

- 路由表 9 行；另有一个磁盘上存在、路由表里没有的领域目录；路由表里有一行指向不存在的目录。
- 事项：已逾期 2 条、今天到期 1 条、未来 7 天 2 条、更晚 1 条；`@wait` 2 条（其中 1 条带 `@due`）；`@every` 2 条；无日期 5 条；已完成 `[x]` 带日期 1 条、不带日期 1 条；未知标签 1 条；不合法的 `@due` 1 条；事项文本里带 Markdown 链接 1 条。
- 「更新于」：3 个领域超过 14 天，1 个领域没有「更新于」。

## 12. 迭代 2：Git 视图与自动刷新（2026-11-21）

依据：真实 PersonalOS 的提交历史（2026-11-21 只读统计，不含正文）：约 25 笔提交，没有合并提交；多数提交同时改一个领域和当月日志，少数一次改了十几个目录；标题开头多为 `[领域]`，也有 `[验收]`、`[蓝图]` 这类非领域标签和 `阶段 N：…`；有改名；最大的一笔约 1200 行新增；路径是中文，Git 默认会把它转义成八进制。

### 12.1 只读调用 Git

- **仓库位置**：`<root>/.gitdata.nosync` 是目录时，用它作 git 目录、`<root>` 作工作区；否则 `<root>/.git` 存在时按普通仓库；都没有时 Git 不可用（`no_repo`）。**不得读到 PersonalOS 以外的仓库**：环境变量 `GIT_CEILING_DIRECTORIES` 设为 root 的上一级，并核对 `rev-parse --show-toplevel` 与 root 的真实路径一致，不一致按 `no_repo` 处理。
- **只允许** `rev-parse`、`log`、`show`、`status` 四个子命令。用 `execFile`，不经 shell。参数在代码里写死或经过校验：提交号只接受 `^[0-9a-f]{7,40}$`；按领域查询的路径只能来自路由表或磁盘上的领域目录，不直接用请求里的字符串。
- 每次调用固定带：`-c core.quotepath=false -c core.fsmonitor=false -c color.ui=false --no-pager`；`log`、`show` 再加 `--no-ext-diff --no-textconv`。环境变量：`GIT_OPTIONAL_LOCKS=0`（`status` 不改写索引）、`GIT_TERMINAL_PROMPT=0`、`GIT_LITERAL_PATHSPECS=1`。超时 5 秒，输出上限 8 MB。
- 解析机器格式（`-z`、`%x00`、`%x1e` 分隔），不解析给人看的输出。
- **隐藏路径**：路径里任一段以 `.` 开头的文件（如 `.claude/…`、`.gitignore`）从文件列表、差异、未存档改动里一律去掉。一笔提交只改了这类文件时提交照常列出，文件列表为空，注明「只改了隐藏文件」。
- **跨隐藏边界的改名**（2026-11-21 答复 Codex P5a 停工问题）：一律按可见的一端处理，界面和接口里都不出现隐藏路径。
  - 隐藏 → 可见：当作新增 `A`，路径取新路径，差异是新文件的全部内容（全为新增行）；
  - 可见 → 隐藏：当作删除 `D`，路径取旧路径，差异是旧文件的全部内容（全为删除行）；
  - 两端都可见：保留 `R`；两端都隐藏：整条去掉；
  - 文件数、增删行数、`domains` 归属都按处理后的结果计算；
  - 未存档改动（12.4）用同样的规则；
  - 实现提示：`-M` 下 git 会把这类改名合成一条 `R`，差异头里带着隐藏路径。可以对这几个文件再用 `show --no-renames` 加可见路径限定取一次，得到普通的新增或删除差异。
- **失败**：git 命令不存在、仓库不可用、超时或退出码非 0 时，Git 部分返回 `available: false` 和 `reason`（`no_repo` / `git_missing` / `git_error`），页面其他部分照常。返回里不带 git 的原始错误文本，因为里面可能有绝对路径。

### 12.2 提交与领域

- 提交对象：`sha`、`shortSha`（7 位）、`date`（作者时间，ISO 8601，带时区）、`subject`、`body`、`domain` 或 `tag`、`domains`、`files`、`insertions`、`deletions`、`fileCount`、`hiddenOnly`。
- `domain` / `tag`：标题以 `[X]` 开头时，规则同日志的方括号（1.7）：X 是领域名（含「我」）就填 `domain`，否则填 `tag`。其他标题（如 `阶段 3：…`）两者都不填。
- `domains`：按改动的路径归属。`我/**` 归「我」，`领域/<名>/**` 归该领域（未登记的领域目录也算）。去重，按路由表顺序排。只改了日志、协议、蓝图等根目录文件的提交，`domains` 为空。
- `files`：`status`（`A` / `M` / `D` / `R`）、`path`、`oldPath`（仅改名）、`insertions`、`deletions`、`binary`。改名用 `-M` 识别。以后出现合并提交时，按第一个父提交算差异。
- 按领域查询提交：路径限定为该领域目录（`我/`、`领域/<名>/`）。

### 12.3 差异

- 单笔提交的差异按文件返回统一差异格式（`-U3`）的行。网页用等宽字体渲染：新增行 `--bm-accent-soft` 背景，删除行 `--bm-danger-soft` 背景，`@@` 行灰色。
- **上限**：每个文件 500 行，一笔提交合计 3000 行。超出的截断，标 `truncated`，界面写「差异太长，只显示前 N 行」。二进制文件只写「二进制文件」，不返回内容。
- 文件当前仍存在时给「打开当前版本」（进阅读器）；已删除或已改名走的旧路径不给。

### 12.4 未存档改动

- 用 `status --porcelain=v1 -z --untracked-files=all` 读工作区，返回 `uncommitted: { count, files: [{ status, path }] }`，隐藏路径去掉。
- 界面说明：「N 个文件有未存档的改动，晨间存档时会提交。」只读，没有提交按钮。

### 12.5 页面

- **提交列表**：
  - 按日期倒序，按日期分组，组标题同日志（`11-20 周四`，吸顶）。
  - 行高 34px，依次是：短提交号（等宽、灰色）；标题（单行省略）；领域标签（取 `domains`，最多 2 个，多的写 `+N`）；`tag` 用灰色标签；`+N −M`；时间 `HH:MM`。

### 12.6 自动刷新

- **服务端监听**：第一次收到 PersonalOS 请求时开始监听（构造时不做 I/O），服务关闭时释放。
  - 用 `fs.watch(root, { recursive: true })`，事件去抖 300ms。
  - 非隐藏路径的变化使 `version` 加一。
  - Git 目录里 `HEAD`、`packed-refs`、`refs/**`、`logs/HEAD` 的变化使 `gitVersion` 加一；`index`、`objects/**`、`*.lock` 的变化忽略。
  - `fs.watch` 抛错或报告错误时，改为每 10 秒比对一次签名：非隐藏文件的「路径 + 大小 + 修改时间」，以及 Git 的 `HEAD` 和 refs。这时 `mode: 'poll'`。PersonalOS 目录不存在时 `mode: 'off'`，同样每 10 秒检查目录是否出现，出现后改回监听。
  - **不加跨请求的解析缓存**：真实库约 30 个文件，每个请求现读，正确性优先。
- **接口** `GET /api/v1/personalos/version`：返回 `{ ok, version, gitVersion, changedAt, mode }`。`version` 和 `gitVersion` 是字符串，含服务启动标识，服务重启后一定和之前不同。需要口令，`cache-control: no-store`。
- **网页**：
  - PersonalOS 的五个页面挂一个版本查询，每 5 秒一次，页面不可见时停。
  - `version` 变了：概览、今天、领域详情、资料登记、日志和 PersonalOS 文件查询失效重取。`gitVersion` 变了：提交相关查询失效重取。原有的 30 秒兜底和窗口聚焦刷新保留。
  - 后台重取时不显示加载态，不清空列表，不丢滚动位置、选中项和展开状态。
  - 阅读器打开的文件变化后内容原地更新；文件被删除时，阅读器显示「这个文件已不存在」。
- **搜索**：服务端收到变化后，下一次搜索强制刷新索引里 PersonalOS 的部分，复用现有的按修改时间增量刷新。
- **页头**：PersonalOS 的五个页面在页头右侧（搜索框左边）显示「数据读取于 HH:MM」，取当前页主查询的读取时间。
  - 悬停说明刷新方式：`watch` 写「文件变化后几秒内自动刷新」；`poll` 写「每 10 秒检查一次变化」；`off` 写「自动刷新不可用，切回窗口时刷新」。
  - 点击立即刷新。

## 13. 迭代 3：写得回（2026-11-22）

依据：[ADR 0011](../decisions/0011-personalos-desk.md) 决定 5，以及 PersonalOS 的 `协议/更新.md`（2026-11-22 只读查看）。看板只做两种写入：**速记**和**完成待办**。效果必须和 agent 按协议做的一样。现状、近期变化、知识、事项文件、收件箱分拣，仍由 agent 在会话里做。

### 13.1 写入通道（共用规则）

- **只写这些文件**：`收件箱.md`；路由表里各领域（含「我」）的 `状态.md`；`日志/YYYY-MM.md`。路径一律在服务端由领域 id 或固定名字拼出，不接受请求里的路径。其他文件一律不写，不删文件，不建目录（`日志/` 已存在；当月日志文件不存在时可以新建）。
- **写前重读**：服务端以磁盘上的当前内容为准，和请求带来的 `hash`（网页读到的文件内容的 SHA-256）比对。不一致就返回 409 `conflict`，不写。网页提示「文件刚被改过，已刷新，请再试一次」，并重取数据。
- **原子写**：先写同目录下的隐藏临时文件（`.<原名>.bm-write`），再改名覆盖；失败时删掉临时文件。保留原文件的换行风格和结尾换行。
- **串行**：同一个服务里的写入排队执行，一次一个。
- **预览**：完成待办先调用 `dryRun: true`，返回将要改的每个文件的差异和提交说明。用户在确认框里点「完成」后，再用同一个 `hash` 正式写入。速记的输入框就是预览：下方显示将要追加的那一行，回车就是确认。
- **Git 提交**（只用于完成待办）：
  - 写入前先查这两个文件有没有未提交的改动（`status --porcelain -- <文件>`）。有的话照写，但**不提交**，结果里写 `committed: false, reason: 'dirty'`，界面说明「已写入，未提交：文件里还有别的未存档改动，晨间存档会带上」。
  - 否则 `git add <这两个文件>`，然后 `git commit -m "[领域] 完成：事项"`。使用用户自己的 Git 配置（作者和 agent 提交时一样），但关闭钩子（`-c core.hooksPath=/dev/null`）。
  - 没有仓库（`no_repo`）、git 不存在或提交失败（`git_error`）时，文件照写，`committed: false` 并带原因；不回滚已写的文件。
  - 只允许 `add`、`commit` 两个写入命令，加 12.1 的四个只读命令。不 push、不建分支、不 reset、不改写历史。
- 写入后监听会让 `version`、`gitVersion` 变化，各页自动刷新（12.6）。写入接口的返回里也带上新的 `hash`，网页立即让相关查询失效。

### 13.2 速记

- `POST /api/v1/personalos/inbox`，请求体 `{ text }`。
- `text` 去掉首尾空白后不能为空，最长 500 字，不能有换行（有换行返回 400 `invalid_input`）。
- 在 `收件箱.md` 末尾追加一行 `- YYYY-MM-DD 内容`，日期取「今天」（1.5）。文件没有以换行结尾时，先补一个换行。
- 不更新「更新于」，不写日志，不提交（协议：收件箱直接写，由晨间存档带上）。
- `收件箱.md` 不存在时返回 404 `not_found`，不新建。
- 界面：今天页「收件箱」区块上方一行输入框，占位文字「速记：一句话，回车记下」。输入时下方灰字显示将要追加的那一行。回车后清空输入，收件箱列表里出现新的一条。收件箱区块即使为 0 条也显示输入框。命令面板加「知识台：速记」，聚焦这个输入框。

### 13.3 完成待办

- `POST /api/v1/personalos/todos/complete`，请求体 `{ domain, line, raw, hash, dryRun }`：`domain` 是领域 id，`line` 是行号（1.4），`raw` 是那一行的原文，`hash` 是该 `状态.md` 的 SHA-256。
- 服务端校验：领域存在；`hash` 一致；第 `line` 行和 `raw` 完全相同，在「未结事项」节里，而且是未完成的 `- [ ]` 行。任何一项不符：`hash` 或行内容不符返回 409 `conflict`，其他返回 400 `invalid_input`。
- **普通事项**：`[ ]` 改成 `[x]`，行尾加 ` YYYY-MM-DD`（今天）。其余文字不动。
- **周期事项**（有 `@every`）：不打勾，把 `@due(旧日期)` 换成下一次日期。从旧日期起按周期累加，直到日期晚于今天，至少加一次。`w` 加 7 天；`m` 加自然月，日子超过当月天数时取月末；`y` 加一年，2-29 遇到平年取 2-28。没有合法 `@due` 的周期事项返回 400，提示「周期事项缺少截止日期」。
- **更新于**：把该文件前 10 行里第一个「更新于」的日期改成今天，保留原来的冒号写法。没有「更新于」时不加，结果里带一条警告。
- **日志**：在 `日志/YYYY-MM.md`（今天所在月份）末尾追加 `- YYYY-MM-DD [领域] 完成：事项文本`。周期事项写 `- YYYY-MM-DD [领域] 完成：事项文本（下次 YYYY-MM-DD）`。事项文本是去掉标签后的文本（1.4）。当月文件不存在时新建，第一行写 `# YYYY-MM 日志`，空一行后写条目。
- **提交说明**：`[领域] 完成：事项文本`，单行，超过 72 个字符时截断并加 `…`。
- **返回**：`{ ok, dryRun, files: [{ path, lines }], message, committed?, reason?, sha?, hash, warnings }`。`lines` 是统一差异格式的行。
- **界面**：
  - 今天页和领域详情里事项行的空心圆变成可点的复选框（`role="checkbox"`）。键盘：选中行后按 `x`。
  - 点击后调用预览，弹出确认框，标题「完成这件事？」，内容依次是：事项文本；会改哪些文件（`状态.md`、日志）；提交说明；可展开的差异。按钮「完成」（主按钮）和「取消」。Esc 取消。
  - 确认后：普通事项从未结列表消失，周期事项换到新日期所在的分组。提示条按结果写：「已完成并提交」；「已完成，未提交：……晨间存档会带上」；或 409 的冲突提示。
  - 等待中（`@wait`）的事项同样可以完成。
- 领域详情标题行的「只读」标去掉。阅读器仍然只读。

### 13.4 测试

- 写入测试只在临时副本上做：用 `createGitFixture` 现建副本，或复制 fixture；不碰仓库里的 fixture，也不碰真实 PersonalOS。
- 单元测试至少覆盖：
  - 下一次日期：`1w`；`1m` 跨月末（1-31 → 2-28 / 2-29）；`1y` 遇到 2-29；逾期好几个周期；正好今天到期；
  - 普通完成和周期完成的行内容；
  - 「更新于」的替换，以及没有「更新于」时的警告；
  - 日志追加，以及新建当月文件；
  - 409：`hash` 不符、行内容不符；
  - 400：行不在「未结事项」节、行已完成、周期事项没有 `@due`、领域不存在；
  - dry-run 不改任何文件，git 目录哈希不变；
  - 两个文件里有未存档改动时只写不提交；没有仓库时只写不提交；
  - 提交成功后，`log -1` 的说明和改动的文件正确，工作区里其他未存档改动没有被提交；
  - 速记：追加格式、缺结尾换行、空文本、换行、超长、文件不存在；
  - 并发：两个完成请求同时到达时排队执行，后一个因 `hash` 变化得到 409。
- 走查：在可写副本服务上覆盖复选框、确认框、取消、完成后列表变化、周期事项换组、冲突提示、速记追加、`x` 快捷键；截图有确认框（1440 / 720，深浅色）。
