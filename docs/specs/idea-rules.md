# 灵感卡片规则

- 日期：2026-10-10
- 来源：灵感台 Python 实现（`bluemanta-workbench/modules/inspiration_desk/core/`，业务 schema 6，`domain.py`、`classify.py`、`schema.py`），由 Claude Code 提炼。实现者不需要、也不应该去读那份 Python 代码，以本文为准。
- 适用：`cardType: 'idea'` 的卡片。标注"所有卡片"的条目对 scene / note 同样适用。

## 1. 内容与标题

- **至少要有内容：** 新建或修改后，标题、正文、附件三者至少有一个非空，否则 `invalid_input`。
- **标题长度：** ≤ 80 个字符（Unicode 码位）。
- **兜底标题：** 用户没给标题（缺省或空字符串）时，自动生成：把正文的连续空白折叠成一个空格、去掉首尾空白后，取前 80 个字符；正文也为空时，标题为「未命名灵感」。
- **`titleOrigin`：** 用户给了非空标题记 `user`；自动生成记 `fallback`。
- **修改时：** 输入里没有 `title` 字段，标题和 `titleOrigin` 保持不变（即使正文变了，兜底标题也不重算）；输入里有 `title`，按上面的规则重新确定。

## 2. 原始输入 `rawInput`

- 写入后不可修改（T1 已实现）。
- **新建时可省略。** 省略时自动生成：`{ status: 'present', channel, text }`，其中 `text` 取正文，正文为空时取标题；`channel` 由来源决定：`source.kind` 为 `agent` 时记 `agent`，否则记 `web`。
- `channel: 'bot'` 只在调用方显式传入时使用（例如 Grok Bot 写入、或从 workbench 导入来源为 bot 的记录）。
- 历史数据用 `{ status: 'legacy' }`，只在导入时出现。

## 3. 分类

- 五类单选：`product` 产品想法 / `learning` 学习备忘 / `work` 工作事务 / `life` 生活随想 / `other` 其他。
- **用户指定优先：** 输入里带 `fields.category` 时，使用它，`categorySource` 记 `user`。
- **用户改过就不再自动覆盖：** 已有记录的 `categorySource` 为 `user` 时，之后的修改即使改了标题或正文，也保持原分类。
- **否则自动分类：** 新建，或修改时原 `categorySource` 为 `auto`，用标题和正文按下面的关键词规则重新分类，`categorySource` 记 `auto`。
- 自动分类只用本地关键词，不调用任何模型或网络。

### 关键词规则

1. 标题、正文各自：转成小写（Unicode casefold），连续空白折叠成一个空格，去首尾空白。两者都为空时直接返回 `other`。
2. 对 product、learning、work、life 四类分别计分：`分数 = 标题命中分 × 2 + 正文命中分`。命中分是该类每个命中词的权重之和，同一个词在同一段文本里只算一次。
3. **匹配方式：** 纯字母数字词（正则 `^[a-z0-9][a-z0-9+\-]*$`，如 `mvp`、`app`、`okr`）按整词匹配，前后不能紧挨字母或数字；其他词（含中文）按子串匹配。
4. 取分数最高的一类；并列时按 product → learning → work → life 的顺序取靠前的；最高分为 0 时返回 `other`。

| 类别 | 权重 4 | 权重 2 |
|---|---|---|
| product | 商业模式、产品想法、功能设计、用户需求、变现路径、付费订阅、定价策略、增长策略、竞品分析、最小可行产品、落地页、产品功能、商业点子、收费模式 | mvp、saas、产品、功能、商业、点子、用户、需求、变现、定价、订阅、原型、竞品、市场、增长、创业、收费、付费、转化、发布、app、版本、原型图 |
| learning | 学习备忘、知识点、读书笔记、听了播客、课程笔记、复习要点、概念解释、论文、方法论 | 学习、读书、播客、笔记、课程、复习、记住、摘录、读到、原理、教程、英语、书里、听课、知识、概念、podcast、lesson |
| work | 工作事务、售前、职场待办、客户跟进、报价、合同、周报、会议纪要、项目进度、出差、工单、交付 | 客户、职场、待办、会议、同事、老板、提案、跟进、汇报、邮件、上班、工作、对接、deadline、okr |
| life | 生活随想、散步时、心情很、晚饭、家人、想念、感触 | 生活、散步、随想、心情、情绪、孩子、旅行、天气、身体、睡觉、周末 |

注意：同一个词可能同时出现在高权重词和低权重词里（如"产品想法"和"产品"），按表分别计分，即"产品想法"命中时两者都加分。

## 4. 回收站（所有卡片）

- **在回收站里的卡片不能修改，** 也不能追记、删除追记、收藏；要先恢复。返回 `invalid_input`，消息说明"先恢复"。
- **彻底删除只能对回收站里的卡片执行。** 不在回收站的返回 `invalid_input`。同样适用于任务（`task.purge`）。
- 彻底删除时，附件文件的删除由附件存储负责（T5 实现）；core 返回被删卡片的附件 id 列表，供调用方清理文件。

## 5. 收藏

- 收藏 / 取消收藏不算编辑：`updatedAt`、`updatedBy` 保持不变；`rev` 仍然加 1（用于版本冲突检测），并照常写历史。
- 只有人能执行（T1 已实现）。

## 6. 追记（extensions）

- 是用户对一条灵感的后续补充，不是评论，按时间正序排列。
- **只有人能追加**（`source.kind` 为 `agent` 时 `forbidden_source`）。这是灵感台已有的产品规则：agent 和 Bot 不得自动写追记。
- 删除追记：人和 agent 的限制同追加。
- 单条追记 ≤ 8000 字符，不能为空。
- 追加或删除追记算编辑：更新 `updatedAt`、`updatedBy`、`rev`。

## 7. 搜索（供 T5 面板和 T6 agent 工具使用）

- 搜索范围：标题、正文、原始输入的 `text`、分类的中文名称（如输入"产品想法"能搜到该分类的卡片）。
- 关键词按空白切分，所有词都要命中（AND），不区分大小写。
- 默认只搜不在回收站的卡片。
- 每条结果返回：卡片本身、命中的字段（`title` / `body` / `rawInput` / `category`，按此优先级取第一个）、约 120 字的摘录（命中位置前后截取）。
- 结果按创建时间倒序。

## 8. 附件（元数据，所有卡片）

- 灵感最多 4 个附件（T1 已实现上限）。
- 允许的类型：`image/jpeg`、`image/png`、`image/gif`、`image/webp`；单张 ≤ 8 MB；宽高 ≤ 16384 像素。
- 文件上传、存储、读取在 T5 实现，T3 只负责元数据校验。
