- 日期：2026-10-11
- 状态：已批准（2026-10-11），进行中
- 目标：日常用的灵感台换成按设计规范实现的网页版，浏览器里和 dsh 里体验一致；dsh 插件里不再有业务界面。
- 依据：[ADR 0005](decisions/0005-web-app-dsh-entry.md)、[设计规范 v1.0](design/DESIGN.md)、[S3](../spikes/s3-embed/README.md)
- 范围：本地服务、网页版灵感台（功能对齐阶段 1，新增快速记录和命令面板）、dsh 插件改为只嵌入网页、S3 遗留验证项、T9 侧栏品牌、阶段 1 试用反馈。
- 不做：内容线（阶段 2 暂缓）、项目与任务界面、迁往云端、账号登录。
- 实现：Cursor；验收与合并：Claude Code（ADR 0004）。

## 1. 和插件版灵感台不同的地方

功能对齐阶段 1；布局和交互按设计规范。`idea-ui.md` 与设计规范冲突的地方，以设计规范为准，T12 开工前我把 `idea-ui.md` 改成 v3。

| 项 | 插件版（阶段 1） | 网页版 |
|---|---|---|
| 二级菜单（清单 / 统计 / 回收站） | 单独占一列 | 页头里的分段控件 |
| 新增 | 详情区的「新增灵感」tab | 列表顶部的快速记录卡片（`N`），可贴图 |
| 详情 tab 上限 | 8 个 | 6 个 |
| 分栏宽度 | 拖列表宽度，默认 380px | 拖详情宽度，默认 420px，320–720px |
| 列表行 | 两到三行卡片，带缩略图 | 34px 单行：星标、标题、摘要、命中字段、分类、来源、时间；有图时标题后显示图标和张数，缩略图只在详情里显示 |
| 移入回收站 | 直接执行 | 直接执行，轻提示里带「撤销」 |
| 命令面板 | 无 | `⌘K`：命令 + 灵感搜索 |
| 键盘 | 少量 | 设计规范第 8 节全套 |
| 嵌在 dsh 里 | 跟随 dsh 配色 | 自己的配色，只有深浅色跟随 dsh |
| 从统计页点某天 | 回清单并按日期筛选 | 不变，日期作为可清除的筛选胶囊 |

不变：搜索范围、分类与收藏筛选、详情内容顺序、原文显示规则、追记（界面上仍叫「延展」）、图片规则（最多 4 张、8 MB、四种格式）、编辑冲突处理、彻底删除确认、上海时区。

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | React + TypeScript | 和 dsh 同一技术栈，工具卡片等将来要互相参照；Cursor 最熟；生态里的无样式组件最全 |
| 构建 | Vite，产物是静态文件 | 构建快；产物就是一个目录，本地服务直接托管，将来放到云端静态托管也不用改 |
| 组件 | **无样式组件**：Radix Primitives 按需引入（对话框、确认框、提示）；命令面板用 cmdk。**不用带默认样式的组件库，不用 Tailwind** | 设计规范要求贴合 `tokens.css`，无样式组件只提供行为和无障碍（焦点管理、esc、`aria-*`），外观全部自己写，不会出现「设计迁就组件默认样式」 |
| 样式 | CSS Modules + `docs/design/tokens.css` 的变量 | 直接引入仓库里那一份 `tokens.css`，不复制，保证视觉数值只有一个编辑入口；组件样式只用 `--bm-*` 变量 |
| 数据请求 | TanStack Query | 自带缓存、重试、窗口切回时刷新；设计规范要求「读取失败时继续显示缓存并持续提示」，它直接支持 |
| 路由 | wouter（约 2 KB） | 只有几条路径：`/ideas`、`/ideas/stats`、`/ideas/trash`、`/ideas/:id` |
| 本地服务 | Hono + `@hono/node-server` | 现有接口处理函数已经是 `Request → Response` 写法，可以原样迁过去；Hono 同一份代码也能跑在云端运行时，符合 ADR 0005 第 4 条 |
| 测试 | Vitest（接口、组件）+ Playwright（走查脚本） | Playwright 把浏览器走查写成可重复运行的脚本，在 CI 里跑，并按设计规范第 10 节的尺寸和深浅色出截图 |

打包与提供方式：`packages/web` 构建到 `packages/web/dist`；本地服务托管这个目录（带哈希的资源长缓存，`index.html` 不缓存，未知路径回落到 `index.html`）。网页和接口同源，不需要跨域设置。

## 3. 本地服务与嵌入的约定

- **包名与目录：** 本地服务 `packages/server`，网页 `packages/web`（AGENTS.md 的目录表随 T11、T12 更新）。
- **地址：** 只监听 `127.0.0.1:4310`，固定端口，方便收藏；端口被别的程序占用时报错退出，不随机换。
- **鉴权：** 本机口令，32 字节随机数，首次启动生成，存在数据目录的 `local-server.json`（权限 600）。接口要求 `Authorization: Bearer <口令>`；口令校验集中在一个中间件，将来换账号登录只改这里。
- **Host 校验：** 只接受 `127.0.0.1:4310` 和 `localhost:4310`，防 DNS 重绑定。不设 CORS 头，其他网站读不到接口。
- **网页拿口令：** 用 URL 的 `#token=…` 传入（`#` 后面的内容不会发给服务器、不进日志），网页读到后存进本地存储并从地址栏抹掉。独立打开时用一条命令打开浏览器；之后收藏 `http://127.0.0.1:4310/` 即可。
- **接口：** `/api/v1/…`，按资源设计（灵感、延展、附件、健康检查），不出现本机路径；保留写入协议：`requestId` 幂等、`rev` 冲突、来源统一记为人（`desktop`）。`GET /api/v1/health` 不要口令，只回答「是不是 bluemanta 服务、什么版本」，供 dsh 插件判断服务是否已在运行。
- **外部写入可见：** Grok Bot、MCP、agent 写入的灵感，网页在切回窗口时或 30 秒内显示出来，不用刷新。
- **嵌入：** dsh 插件在 iframe 里打开 `http://127.0.0.1:4310/ideas?embed=main`（右侧栏用 `embed=sidebar`），`#` 里带口令和 dsh 页面的 origin。网页只接受这个 origin 的父窗口发来的消息，也只往这个 origin 发。
- **消息桥（在 S3 的 `bm:*` 上扩展）：**

| 方向 | 消息 | 作用 |
|---|---|---|
| 网页 → dsh | `bm:ready` | dsh 回发主题 |
| dsh → 网页 | `bm:theme { dark }` | 只取深浅色，设置 `data-theme` |
| 网页 → dsh | `bm:openSidebar { id, title }` | 在右侧栏打开这条灵感 |
| 网页 → dsh | `bm:quote { id, title }` | 在对话中引用（具体做法由 S4 定） |
| 网页 → dsh | `bm:dirty { dirty }` | 右侧栏 tab 有未保存修改，关闭前由 dsh 确认（保留 T10 的行为） |
| 网页 → dsh | `bm:shortcut { key }` | 焦点在网页里时，转发 dsh 需要的少数快捷键（清单由 S4 定） |
| dsh → 网页 | `bm:result { ok, reason }` | 执行结果；不在对话里时回原因，网页用轻提示说明 |

- **agent 工具：** 三个工具和工具卡片留在 dsh 插件，继续直接调用 core（和命令行、MCP 一样）；工具卡片里的「打开」改为在右侧栏打开网页。

## 5. 收尾

T16 合并后：

1. **备份真实数据：** 把 `~/Library/Application Support/BluemantaDesktop/` 整个复制到 `backups/<时间戳>-phase-1-5/`（只复制，不改动）。
2. **切换前留底：** 用 `sqlite3 -readonly` 导出一份对照清单：每条卡片的 id、rev、更新时间、是否在回收站、是否收藏、延展数、附件数，以及总数（灵感、回收站、收藏、附件）。
3. **启动本地服务：** 安装开机自启（写入你的 `~/Library/LaunchAgents`，2026-10-11 已同意）；确认 `http://127.0.0.1:4310/` 能打开。
4. **切换 Desktop：** 插件仍是 link 安装 `packages/dsh-plugin`，路径不变；`main` 更新、构建后，**请你退出并重开 DeepSeek Harness**（你正在用时我不强制重启）。确认左侧栏「灵感台」显示的是网页版，右侧栏和工具卡片的「打开」可用，侧栏品牌已换。
5. **数据无损核对：** 经接口读出全部灵感，和第 2 步的对照清单逐条比对，必须完全一致；抽查长标题、legacy 原文、原文与正文重复、带图片的那几条在网页上的显示。全程只读。
6. **写入核对：** 真实数据上的写入由你在试用时自然完成（记一条、收藏、追记），我事后只读核对：来源记为 `desktop`，rev 递增，操作历史完整。我不在真实数据上做写入测试。
7. **Grok Bot 与 MCP 不受影响：** 命令行和 MCP 的代码路径不变；在隔离数据目录上跑一遍 `idea.js add/search/get` 和 MCP 三个工具；再请你让 Grok Bot 记一条，确认它在 30 秒内出现在网页上。
8. **S3 遗留项在 Desktop 里补齐：** Desktop 退出后，插件拉起的服务是否停止（开机自启的那个应继续运行）；嵌入状态控制台有无错误；快捷键转发是否生效。
9. **更新文档：** `vision.md` 记录决定、本文件补收尾记录、`AGENTS.md` 目录表与当前阶段、`docs/local-update.md`。推送前问你。
10. **你试用：** 连续一周日常记录和回看都用网页版（浏览器和 dsh 里），观感认可后，把截图登记为设计基线（设计规范第 10 节第 6 条）。

## 6. 已定的技术约束

- 沿用阶段 1：`node:sqlite`，不用原生扩展；Node ≥ 24；用户数据目录不变。
- 正本仍是同一个 SQLite，**不迁移数据**。本地服务、dsh 插件（agent 工具）、命令行、MCP 四个进程共用一个库，靠 WAL 和 core 已设的 5 秒忙等待；T11 用并发写入测试确认。
- 更新代码后，本地服务要重启才会用上新代码；core 遇到比自己新的库结构会拒绝打开，不会写坏数据。
- 网页只经 HTTP 接口访问数据，不读本机路径（ADR 0005 第 4 条）；图片经接口读取。
- 写入类测试一律在隔离目录用虚构数据；真实数据只读检查。

| 风险 | 对策 |
