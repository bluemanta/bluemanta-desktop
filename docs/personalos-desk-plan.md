## 1. 现状

### 1.1 PersonalOS 是什么

`~/Documents/PersonalOS/` 是 Chris 的个人上下文中枢：一棵按生活领域组织的 Markdown 目录，放在 iCloud 里。仓库数据放在目录内的 `.gitdata.nosync/`，只用本地 Git。维护者是 agent（Claude Code、Codex），由 Chris 确认。

| 部分 | 文件 | 结构 |
|---|---|---|
| 入口 | `AGENTS.md`（`CLAUDE.md` 只引用它） | 「关于我」、**路由表**（领域、路径、别名与关键词、典型问题，9 行）、读写规则 |
| 领域 | `我/`，以及 `领域/<名>/` 下的 8 个领域 | 每个领域一份 `状态.md`；有资料时才有 `资料登记.md` |
| 状态 | `状态.md` | 「更新于：年-月-日」+ 四个固定二级标题：现状、未结事项、近期变化、去哪查（`我/状态.md` 是七节）。「去哪查」里有 `###` 外部系统挂接卡片 |
| 待办 | `状态.md` 的「未结事项」 | `- [ ] 事项 @due(日期) @wait(谁) @every(1w/1m/3m/1y)`；完成写 `- [x] … 完成日期`；全库检索 `- [ ]` 即汇总 |
| 资料登记 | `资料登记.md` | 表格：主题、资料、位置、用途、状态（`引用` / `已入库`） |
| 知识 | `知识.md`（用到时再建，目前没有） | 一个主题一个二级标题；工作标准也写在这里 |
| 事项 | `领域/<名>/事项/<事项名>.md`（v0.4 已决定，目前没有） | 固定小节：为什么做、范围与已确认安排、当前情况、资料与成果、重要变化 |
| 收件箱 | `收件箱.md` | `- 日期 内容`，晨间简报时分拣并删除 |
| 日志 | `日志/YYYY-MM.md` | 只追加，`- 日期 [领域] 发生了什么`；阶段交付说明是 `##` 小节 |
| 协议 | `协议/晨间简报.md`、`更新.md`、`知识入库.md` | agent 照做的步骤；每次改状态都要更新「更新于」、写日志、做一次 Git 提交 |

**进展**：阶段 1（骨架）、2（Knowledge 迁移与挂接）、3（访谈填充）已在 2026-11-12 至 2026-11-20 通过验收。阶段 4（收件箱入口）和阶段 5（两周晨间简报试运行，加 10 项真实任务）还没开始。v0.4 的三项决定已在 2026-11-19 拍板，正文还没写。内容上多数领域写着「待补充」，全库只有两条未结事项。

**和知识台有关的已定事项**：PersonalOS 已经取代 `~/Documents/Knowledge` 成为个人知识的正本，旧库原样保留，「等知识台改造完成后再归档」。蓝图 v0.3 第 12 节把「Desktop 知识台改读 PersonalOS」列为后续再议。

### 1.2 知识台现在什么样

- 第一版只读，KB0–KB5 已合并，KB6 已建个人库。**KB7 没做**：10 个真实问题的测试集还没建（数据目录里没有 `knowledge-eval.json`），Desktop 实测和收尾文档也没做。
- 按 Arsenal 结构解析（总索引表、编号分类目录、每个主题四个文件）。两个库：个人 `~/Documents/Knowledge`（已被 PersonalOS 取代）和 Arsenal（只读）。
- 页面有主题、搜索、收件箱三页，配右侧详情卡片和 Markdown 阅读器。FTS5 全文索引同时覆盖两个库和灵感。agent 工具是 route、search、read，MCP 和 dsh 各一套。

### 1.3 差距

PersonalOS 和 Arsenal 是两种东西：Arsenal 是**主题知识库**，PersonalOS 主要装的是**状态和待办**，知识只是其中一小块。所以这次不是给知识台换一个库，而是让它变成 PersonalOS 的**看板**：先回答「今天有什么事」「各方面现在怎么样」「最近改了什么」，再回答「某个东西在哪」。

## 2. 定位

> 知识台改为 PersonalOS 的可视化界面：只读呈现今天的事、各领域状态、资料和变化；检索覆盖 PersonalOS、Arsenal 和灵感；写入只做少数几个严格照 PersonalOS 协议执行的动作。

PersonalOS 的读写主体仍然是 agent，网页不替代晨间简报会话，只让人一眼看到 agent 维护的结果，并发现过期和缺口。

## 3. 原则

1. **正本在 PersonalOS 的 Markdown 里。** Desktop 只解析、只建派生索引，不导入 SQLite，不双写（硬规则 1、ADR 0009 决定 4 继续有效）。
2. **解析要宽容。** 真实文件会偏离模板（现状里有 `###` 小节和加粗段落，「去哪查」里有挂接卡片）。按 `##` 切节，认得的结构化展示，认不出的原样渲染 Markdown，不报错、不丢内容。
3. **结构跟着内容长。** `知识.md`、`事项/`、`人物/` 现在都没有，界面要能在它们出现时自动显示，没有时不留空壳。
4. **如实呈现。** 「待补充」「（推断）」「未核验」用标记显示，不把它们当成事实；等待事项没有起始日期时显示「未记录」，不推算（同晨间简报协议）。
5. **写入照协议走。** 网页能做的写入，效果必须和 agent 按 `协议/更新.md` 做的一样：写前重读、更新「更新于」、追加日志、本地 Git 提交（只暂存本次文件，说明写 `[领域] 做了什么`）。先预览，用户确认后再写。
6. **私人数据不进仓库。** PersonalOS 含健康、财务摘要。测试、走查和截图一律用虚构的 PersonalOS fixture（硬规则 3）。

## 4. 页面结构

模块仍是网页里的「知识台」（显示名见决策题 5），页头分段控件改为：**今天 / 领域 / 资料 / 动态 / 搜索**。

| 页面 | 内容 | 数据来源 |
|---|---|---|
| **今天**（默认） | 按晨间简报的顺序：已逾期、今天到期、未来 7 天、等待中（等了多久或「未记录」）、无日期事项（最多 3 条）、过期提示（「更新于」超过 14 天的领域）、收件箱未分拣条数。每条标领域，点开跳到该领域 | 全部 `状态.md` 的未结事项、「更新于」、`收件箱.md` |
| **领域** | 9 张领域卡片：领域名、更新于（过期标红）、未结事项数、「待补充」数、最近一条变化。点开右侧详情：现状、未结事项、近期变化、去哪查（挂接卡片单独成块，标「只读」）、资料登记、事项、知识 | 路由表、`状态.md`、`资料登记.md`、`事项/`、`知识.md` |
| **资料** | 全库资料登记合成一张表，可按领域、主题、状态筛选；本机路径显示是否存在（不读内容），外部链接只显示 | 各 `资料登记.md` |
| **动态** | 时间线：日志条目按日期倒序，可按领域筛选；交付说明折叠显示。另有「上次以来改了什么」：最近 Git 提交和改动的文件 | `日志/*.md`，本地 Git（只读：`git log`） |
| **搜索** | 沿用现有搜索页。结果分组改为 PersonalOS、Arsenal、灵感；PersonalOS 结果带领域标签，路由表的别名和关键词参与加权 | FTS5 索引 |

阅读器、右侧详情卡片、嵌入模式（`embed=main`、`embed=sidebar`）、快捷键沿用现有知识台和灵感台的做法。收件箱不再单独成页，并进「今天」（决策题 3）。

## 6. 决策题（2026-11-21 已定：全部采用建议答案）

第 5 题没有给建议，按 ADR 0011 决定 8 保留「知识台」；第 7 题按「是」：迭代 1 与 PersonalOS 阶段 5 试运行同步。


1. **定位**：知识台改成 PersonalOS 看板（今天、领域、资料、动态、搜索），而不只是换一个知识库？**建议：是。**
2. **写入**：迭代 3 的速记和勾选待办要不要做？**建议：做，但排在迭代 1、2 验收之后。** 不做的话，网页始终只读，写回全靠会话。
3. **收件箱**：并进「今天」页，不单独成页？**建议：并入。**
4. **待办正本**：仓库里另一个会话的任务台草案（`docs/task-desk-plan.md`，2026-10-22）计划在 core 里做 issue 并取代 Linear；而 PersonalOS 已经把个人待办记在各 `状态.md` 里。两边都做会让个人待办有两份正本。**建议：个人待办的正本是 PersonalOS；任务台草案只管开发 issue，或者暂停。** 这一题定了再写 ADR。
5. **名称**：侧栏和 dsh 左侧栏的模块名，保留「知识台」，还是改成「PersonalOS」或「个人台」？
6. **Arsenal**：继续作为只读库参与搜索和浏览？**建议：保留。** PersonalOS 本身也把 Arsenal 列为挂接的外部系统。
7. **节奏**：PersonalOS 阶段 5 试运行还没开始。迭代 1 可以和试运行同步，用网页「今天」页对照会话简报，正好作为验收。要不要这样安排？

## 7. 不做

- 不改 PersonalOS 的目录结构、协议和文件格式，界面去适配它。格式要改的话，先改蓝图，再改解析。
- 不读外部系统（日历、Linear、SalesOS、Notion）来补全「今天」页；挂接卡片只展示「去哪查」。
- 不做语义检索、不做图谱、不做统计图表。
- 不把 PersonalOS 内容放进仓库、fixture、截图或 CI 产物。

## 8. 风险

- **解析跟不上格式变化。** PersonalOS 由 agent 维护，写法会漂移。对策：宽容解析加原样渲染兜底；fixture 里收入真实出现过的偏离写法（只用虚构内容）。
- **网页写入和会话写入撞车。** 对策：写前比对哈希；只做速记和勾选两类无需判断的写入。
- **iCloud 未下载的文件。** 另一台设备刚写的文件可能还是占位符。对策：读不到时显示「文件尚未从 iCloud 下载」，不当成空文件。
- **Codex 首次委派曾报 Internal error，且 Codex 沙箱默认不能写 Git 元数据。** 这只影响 Codex 操作 PersonalOS，不影响它在本仓库开发；开发和测试全程用 fixture，不碰真实目录。
