# PersonalOS 看板「接入」页规划

- 日期：2026-11-22
- 状态：已定稿。2026-11-23 Chris 同意第 8 节全部建议答案，决定见 [ADR 0013](decisions/0013-personalos-sources-page.md)，规格见 [specs/personalos-sources.md](specs/personalos-sources.md)
- 依据：[ADR 0011](decisions/0011-personalos-desk.md)、[ADR 0012](decisions/0012-personalos-desk-claude-implements.md)、[规格](specs/personalos-ui.md)、PersonalOS `AGENTS.md`「使用数据源」、本机定时任务盘点（第 2 节）

## 1. 要解决的问题

PersonalOS 的内容越来越多来自外部：微信本机副本、生财有术 MCP、Obsidian 和各处文档，以后还有 Twitter、第三方开源数据。目前有三个缺口：

1. **看不到接了什么。** 来源卡分散在各领域「去哪查」里，资料登记只管文档，没有一张总表说明接了哪些来源、怎么接、授权到哪。
2. **看不到后台在跑什么。** 定时任务分散在 launchd、Codex 自动化、Claude 定时任务三处，各有各的格式，失败了也没人知道（见 2.3）。
3. **不知道数据新不新。** 微信来源卡第 3 步要求"先检查副本是否有可信的同步截止时间"，但现在没有地方能直接看到。

目标：在 PersonalOS 看板里加一页，回答三件事：**接了哪些来源、每个来源现在新不新、后台任务是否正常**。

### 2.3 盘点中发现的问题

微博超话签到的三个 LaunchAgent 从 2026-08-17 建好起，每次运行都失败（错误日志 98 行，全部为 `can't open file …/Documents/Obsidian/微博超话签到方案/weibo_checkin.py: [Errno 1] Operation not permitted`），三个多月里没人发现。原因是 launchd 用 `/usr/bin/python3` 运行，它没有读取 `~/Documents` 的权限。另外这三个任务的标识用了 `com.apple.` 前缀，很容易被当成系统任务忽略。

这个问题本身另外处理，不属于本页范围。它说明本页最有价值的功能是**让失败自己冒出来**。

## 3. 概念

| 概念 | 含义 | 正本 |
|---|---|---|
| **来源** | 一类外部数据，比如微信、Twitter 收藏、某个开源数据集 | PersonalOS 来源卡（用法）+ 来源登记表（结构化字段，见第 4 节） |
| **接入方式** | 查询型（MCP、CLI 现查，不留副本）、副本型（定时同步到本机）、登记型（只登记位置）、推入型（外部写进来，如 Grok Bot 写灵感） | 登记表字段 |
| **定时任务** | 按时间自动执行的程序。可以给来源刷新副本，也可以做别的事（周报、签到） | 各执行方自己（launchd plist、Codex `automation.toml`），Desktop 只读 |
| **新鲜度** | 副本型来源最后一次成功同步的时间，与预期间隔比较，得出正常 / 偏旧 / 过期 | 不存储，每次读取时计算 |

一个来源可以由零个或多个任务刷新；一个任务可以不对应任何来源。

## 4. 正本放在哪

遵守"每类数据只有一份正本"：

- **任务的正本是执行方。** launchd 的 plist、Codex 的 `automation.toml` 已经记录了时间、命令和状态。Desktop 每次读取时去发现，不复制、不另存。
- **来源的说明正本是来源卡**（PersonalOS 已有约定：接入新来源时在领域「去哪查」写一张卡）。
- **新增一份来源登记表**，建议放在 PersonalOS `我/数据源.md`，格式参照 `资料登记.md`，一张表写来源，一张表写要关注的任务：

```markdown
# 我 · 数据源

## 来源

| 来源 | 方式 | 位置 | 刷新任务 | 预期间隔 | 新鲜度探针 | 成功标记 | 来源卡 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 微信 | 副本 | `~/Library/Application Support/wechat-local-vault/decrypted/current/` | `launchd:local.wechat-vault.hourly-refresh` | 1 小时 | `~/Library/Application Support/wechat-local-vault/logs/hourly-refresh.log` | 成功、资源库格式异常 | [微信](状态.md#微信) |
| 生财有术 | 查询 | scys-mcp | — | — | — | — | — |

## 定时任务

| 任务 | 标识 | 用途 | 日志 | 日志可显示 |
| --- | --- | --- | --- | --- |
| 微博超话签到 | `launchd:com.apple.weibo-chaohua-checkin-primary` | 每天签到 | `~/Library/Logs/weibo-chaohua-checkin-primary-error.log` | 是 |
| 售前周报草稿 | `codex:salesos` | 周报 | — | — |
```

登记表只写来源卡里没有的结构化字段（方式、探针、间隔、成功标记、任务标识；字段定义以[规格](specs/personalos-sources.md)第 1 节为准），用法、授权、核对方式仍只写在来源卡里，不重复。按 ADR 0011 决定 3，这个文件的格式要先写进 PersonalOS 蓝图，再改解析。

## 5. 页面

知识台导航新增一页「接入」，放在「资料」后面。页内分两段：**来源 | 定时任务**。

### 5.1 来源

- 每个来源一张卡片：名称、方式标签、位置（本机路径只用 `stat` 判断是否存在）、新鲜度圆点和"最后同步 22:28"、刷新任务名（可点到任务）、来源卡链接（在阅读器打开）。
- 新鲜度规则：距最后成功同步不超过 1.5 倍预期间隔为正常，不超过 3 倍为偏旧，超过 3 倍为过期；查询型、登记型不显示新鲜度。
- 筛选：方式、只看异常。

### 5.2 定时任务

- 列表：任务名、执行方（launchd / Codex / Claude）、时间（把 rrule、`StartCalendarInterval` 翻成"每小时第 5 分""每周六 8:30"）、下次运行、上次结果（成功 / 失败 / 未知）、关联来源。
- 上次结果的取法：launchd 用 `launchctl list` 的最后退出码，加上登记的日志文件修改时间和最后一行；Codex 先只显示启用 / 暂停和下次时间（它的运行记录格式待核对）。
- 点开看详情：命令、日志最后 20 行（只对登记为"日志可显示"的任务显示，因为日志里可能有 cookie 或账号）、plist 或 toml 位置（可复制路径）。
- 最下面折叠一组 **「未登记的自建任务」**：本机发现、但登记表里没有的 LaunchAgent 和 Codex 自动化，提示去登记。识别方法是排除厂商更新器（Google、Setapp 等），**不能**按 `com.apple.` 前缀排除（见 2.3）。
- 常驻服务单独一小组，只显示是否在运行。

### 5.3 今天页联动

今天页顶部加一条提醒行：有任务失败、有来源过期时显示"2 个任务失败 · 1 个来源过期"，点进接入页。全部正常时不显示。

### 5.4 agent 工具

新增只读工具 `bluemanta_sources_status`，返回来源新鲜度和任务状态。agent 回答"最新""今天"这类问题前可以先查副本截止时间，正好对应微信来源卡第 3 步。

## 6. 不做什么

- **Desktop 不当调度器。** 任务照旧由 launchd、Codex 执行，本地服务停了也不影响任务运行。
- **不在网页里新建或编辑任务。** 新任务由 agent 在会话里建好，然后登记；网页只负责看。
- **不显示来源的内容。** 只显示元数据（路径是否存在、时间、计数），不读微信库内容。
- **不做通用连接器框架或插件市场。** 每接一个新来源（Twitter 等）都是单独的小项目，按第 7 节清单接入，看板只负责显示。
- **不做上下文自动改写。** 见决策题 4。

## 7. 新来源接入清单

以后接 Twitter、开源数据等，每个来源按这张清单完成后才算接入：

1. 在对应领域「去哪查」写来源卡：能回答什么问题、从哪里查、授权范围、怎么核对覆盖、怎么用结果（PersonalOS 现有约定）。
2. 在 `我/数据源.md` 登记一行：方式、位置、刷新任务、预期间隔、新鲜度探针。
3. 副本型来源还要有：刷新任务、只写脱敏结果的运行日志、失败时的本机通知（参照微信刷新脚本的做法）。
4. 隐私：副本放在仓库和 PersonalOS 之外，权限 `700`；全文不写进 PersonalOS（PersonalOS「不放进来的东西」）。
5. 在接入页确认它显示正常、新鲜度为绿。

## 8. 决策题（附建议答案）

1. **放在哪里？** 建议：知识台（PersonalOS 看板）新增「接入」页。备选：单独做一个模块。理由：来源和 PersonalOS 是一体的，任务目前也只有十来个；以后量大了再拆，只改显示名和路由。
2. **来源登记表放在哪里？** 建议：PersonalOS `我/数据源.md`，agent 和人都能读，有 Git 历史。备选：Desktop 自己的配置文件，但那样 agent 在会话里看不到。
3. **定时任务看哪些？** 建议：登记过的任务全部显示，另外把"未登记的自建任务"折叠列出，提示登记。备选：本机所有 LaunchAgent 全部显示，但厂商更新器太多，会淹没有用的信息。
4. **后台任务原则怎么写？** PersonalOS 蓝图 v0.3 定了"不建后台任务"，v0.4 输入稿也不采用定时上下文更新，但微信刷新已经是后台任务。建议在 v0.4 写明区分：**数据副本刷新**（机械执行，不调用模型，不改 PersonalOS 文件）允许；**上下文自动改写**（agent 定时改 `状态.md` 等）仍然不做。
5. **第一版要不要带操作？** 建议：第一版只读。第二步再加"立即运行""暂停 / 恢复"，只对 launchd 任务，每次预览命令并确认（硬规则 7：改动用户环境前先问）。
6. **谁来实现？** 建议：按 ADR 0012，由 Claude Code 在 `~/Developer/bm-pos` 实现，说明书和验收记录写在 `docs/tasks/personalos-*.md`。排在迭代 4（agent 工具切到 PersonalOS）之后，或与它合并。

## 9. 迭代划分（决策题确认后细化）

| 迭代 | 内容 | 验收看什么 |
|---|---|---|
| S1 只读接入页 | 登记表解析；launchd、Codex、Claude 定时任务发现；来源和任务两段；新鲜度；未登记任务；今天页提醒；虚构 fixture | 真实环境下能看到微信为绿、微博签到三个任务标红 |
| S2 操作与 agent 工具 | `bluemanta_sources_status`；launchd 任务立即运行、暂停、恢复（确认后执行） | 在接入页手动触发一次微信刷新，状态随之更新 |
| 之后 | 每个新来源按第 7 节清单单独接入 | 来源出现在接入页且新鲜度正常 |
