# ADR 0006：验收按风险分级，走查写成脚本

- 状态：已采纳
- 日期：2026-10-11
- 补充：[ADR 0004](0004-dev-workflow.md) 第 5 条「代码流转」中的验收方式。0004 的其余内容不变。

## 背景

阶段 1 每个任务都由 Claude Code 独立验收：新开 worktree、跑检查、用隔离的 `DSH_HOME` 启动、手动在浏览器里走查。这保证了质量，但纯界面的小改动也要走一遍完整流程，手动走查又不可重复，下次改动还得再点一遍。

阶段 1.5 起界面改成普通网页工程（[ADR 0005](0005-web-app-dsh-entry.md)），可以用 Playwright 把走查写成脚本，在 CI 里自动运行。

## 决定

### 1. 两级验收

| 级别 | 适用 | 做法 |
|---|---|---|
| **轻验收** | 纯界面、小修小补：只改网页的展示和交互，不改接口、不改写入逻辑、不碰 dsh | Cursor 自测，并补齐对应的走查脚本；Claude Code 看 CI、结果评论和 PR 里的截图，对照说明书逐条标注 `verified` / `failed` / `not-run`。截图不对或说明书要求的脚本缺失，按不通过退回 |
| **独立验收** | 涉及正本数据、写入协议（幂等、版本冲突、来源）、对外接口与鉴权、跨系统集成（dsh、Grok Bot、MCP、launchd）、用户环境 | 沿用 ADR 0004：在「当前 main + PR」的合并结果上全新构建，独立运行检查和走查，必要时在隔离 dsh 中实际操作 |

- 级别写在阶段计划的任务表和 issue 说明书里，由 Claude Code 在写说明书时决定。拿不准时按独立验收。
- 轻验收的任务，PR 实际改动超出说明书声明的范围（例如改了接口），自动升为独立验收。
- 阶段末的用户试用不受影响。

### 2. 走查写成脚本

- 网页工程用 Playwright 写走查脚本，跑在虚构数据上，进 CI。
- 每个界面任务按[设计规范](../design/DESIGN.md)第 10 节出截图：1440×900、1280×800、1024×768、720 宽，深浅色各一套，附在 PR 里。
- 新功能连同它的走查脚本一起交付；修 bug 时补一条能复现该 bug 的脚本。
- 只有脚本覆盖不到的部分才手动走查：dsh 嵌入、Desktop 内的行为、视觉观感。

## 后果

- 纯界面任务的验收从「本地构建加手动走查」缩短为「看 CI 和截图」。
- 走查可以重复运行，后面的任务不会悄悄破坏前面的界面。
- 代价：每个界面任务要多写脚本；CI 要装浏览器，运行时间变长。
- 视觉观感仍要靠人看：截图由 Claude Code 先看，阶段末由用户试用确认。
