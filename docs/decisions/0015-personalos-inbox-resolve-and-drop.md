# ADR 0015：看板加「完成」「不跟踪」「不做了」三种写入

- 状态：已采纳（2026-11-27 Chris 同意方案）
- 日期：2026-11-27
- 修订：[ADR 0011](0011-personalos-desk.md) 决定 5（看板只做速记和完成待办两种写入）
- 规则：[specs/personalos-ui.md](../specs/personalos-ui.md) 第 16 节；说明书：[tasks/personalos-inbox-resolve.md](../tasks/personalos-inbox-resolve.md)

## 背景

- 收件箱在看板上只读，只能往里追加速记。顺手做掉的事、觉得不用跟的事，只能等 agent 分拣时再处理，或者自己去改文件。
- 2026-11-27 起收件箱每天 07:30 自动分拣（[ADR 0014](0014-personalos-auto-sort.md)），大多数条目在 Chris 看到之前已经进了领域的「未结事项」。这时想说「这件不用跟了」，对象已经是领域待办；而领域待办在看板上只能「完成」，不能放弃。

## 决定

1. **看板的写入从两种扩到五种。** 原有：速记、完成待办。新增：
   - **收件箱 · 完成**：顺手做掉了。从收件箱删除这一行，日志记 `完成：内容（收件箱 MM-DD）`。
   - **收件箱 · 不跟踪**：觉得不用管了。从收件箱删除这一行，日志记 `不跟踪：内容（收件箱 MM-DD）`。
   - **待办 · 不做了**：领域「未结事项」里的一件事决定不做了。删除这一行，改「更新于」，日志记 `[领域] 不做了：事项文本`。
2. **删除也在日志留原文。** 手机追加的收件箱条目常常还没进 Git，直接删就找不回来。日志里的原文是找回和回顾的依据，「动态」页也能看到哪天处理了哪些事。
3. **收件箱的两种操作不弹确认框，可以撤销。** 点了立即写入，提示条带「撤销」，10 秒内可以恢复。「不做了」改的是领域状态，照「完成待办」的做法先预览、再确认，不提供撤销。
4. **沿用迭代 3 的写入通道**（规格 13.1）：写前比对哈希、原子写、串行、只用 `add` 和 `commit`。收件箱里别人追加、还没提交的行照常一起提交，同 ADR 0014 的例外；日志或 `状态.md` 有别的未存档改动时，照写不提交。
5. **agent 按同一套规则做。** PersonalOS 的 `协议/更新.md` 写进「不做了」和收件箱两种处理的写法，Chris 在对话里说「这件不做了」，结果和在看板上点按钮一样。
6. **由 Claude Code 实现**，做法同 [ADR 0012](0012-personalos-desk-claude-implements.md)。

## 不做

- 不在看板上手动把收件箱条目分到领域，分拣仍由自动分拣和晨间简报做。
- 不批量清理已完成的待办，不改「现状」「近期变化」。
- 「不做了」不给周期事项单独做「跳过这一次」：周期事项选「不做了」就整行删掉，以后不再出现；只想跳过一次，用「完成」顺延。

## 后果

- 好处：收件箱和待办能当场清掉，不用等分拣或开会话。
- 代价：看板直接删除内容的能力变大了。靠三点兜底：日志留原文、每次一笔提交、收件箱操作可撤销。
