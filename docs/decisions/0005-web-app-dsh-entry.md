# ADR 0005：核心功能做成独立网页，dsh 只做入口

- 状态：已采纳；技术可行性已在 web 版和 Desktop App 内验证（S3）
- 日期：2026-10-11
- 取代：[ADR 0001](0001-dsh-shell-data-outside.md) 的决定 1（看板做成 dsh 插件面板）和决定 3（面板页面通过 dsh 适配挂进去）。0001 的决定 2（数据和业务规则放在 dsh 之外）、决定 4（能力层经 CLI 和 MCP 暴露）继续有效。

## 背景

阶段 1 把灵感台做成了 dsh 插件面板（`packages/dsh-plugin/client.js`）。这一过程暴露了几个长期成本：

- dsh 处于预览版，扩展接口在变。T10 中「拦截关闭」要用不在公开接口上的方法，「按灵感查找已打开的 tab」没有接口。
- 插件浏览器端不能引用 dsh 客户端包，界面只能用 dsh 提供的 React 手写 `h()`，没有构建步骤，复杂界面的开发成本高。
- 代码更新后必须退出并重开 Desktop 才生效。
- 界面只能活在 dsh 里，换外壳或给其他系统复用都要重写。

同时，dsh 的价值主要在对话和 agent：工具调用、工具卡片、对话旁的右侧栏。

S3（[spikes/s3-embed](../../spikes/s3-embed/README.md)）验证了另一条路：独立网页可以嵌进 dsh 主区和右侧栏，web 版和 Desktop 中都能读写、同步深浅色主题，并能经消息桥让 dsh 执行「在右侧栏打开」这类操作；dsh 宿主插件也能在 Desktop 中拉起本地服务。

## 决定

### 1. 三层结构

| 层 | 内容 | 位置 |
|---|---|---|
| 数据与规则 | core（存储、写入命令、业务规则）加一个本地服务，对外提供 HTTP 接口；命令行和 MCP 继续保留 | `packages/core`、`packages/cli`、`packages/mcp`，新增本地服务包 |
| 网页应用 | 灵感台、内容线、发布台等全部核心功能的界面，普通前端工程 | 新增网页包 |
| dsh 入口层 | 只保留必须在 dsh 里的部分 | `packages/dsh-plugin` |

### 2. 核心功能做成独立网页

- 网页由独立的本地服务提供（S3 的来源 A），只监听回环地址，接口要求口令；不开 dsh 时在浏览器里直接可用。
- dsh 通过 iframe 把同一个网页嵌进主区和右侧栏。dsh 插件里**不再开发业务界面**。
- 网页使用自己的主题变量；嵌入时由 dsh 发来 `--dsw-alias-*` 的计算值，映射表放在 dsh 入口层。

### 3. dsh 入口层只保留这些

1. 左侧栏入口和装网页的框（主区、右侧栏 tab）；
2. agent 工具注册（T6 的三个工具，以及后续新增的工具）；
3. 对话中的工具卡片（`tool.call.toolview`，只能由插件注册）；
4. 消息桥：网页请求 dsh 执行的操作（例如在右侧栏打开、在对话中引用），协议沿用 S3 的 `bm:*` 消息，按需扩展；
5. 本地服务的启动与停止（Desktop 中用 `process.execPath` 加 `ELECTRON_RUN_AS_NODE=1`）。

### 4. 数据先在本机，设计上为迁往云端留路

内容线的正本先放本机（core 的 SQLite），与灵感一致。为了将来能把部分数据或服务迁到云端，从现在起遵守：

1. **网页只经 HTTP 接口访问数据**，不直接读库、不读本机文件路径；附件也经接口读取。
2. **接口按资源和命令设计**，不出现本机路径、进程等本机假设；同一套接口将来可以由云端服务提供。
3. **鉴权集中在一处**：现在是本机口令，将来替换成账号登录时，只改鉴权层。
4. **保留现有写入协议**：全局唯一 id、`requestId` 幂等、`rev` 冲突检测、来源区分人和 agent、操作历史。这些也是将来本机与云端同步的基础。
5. **时间一律存 UTC**，展示时转换成本地时间（T10 已做）。
6. **不依赖 dsh 宿主提供数据**：dsh 只消费接口，不持有数据。

是否迁云、迁哪部分，等阶段 2 设计内容线时按实际需要再决定，另写 ADR。

### 5. 现有插件界面的过渡

阶段 1 的灵感台插件界面在网页版完成并验收前保持不动。网页版上线后，插件中的灵感台界面和右侧栏详情改为嵌入网页，原有界面代码移除。

## 后果

- **好处**：
  - 核心界面用正常的前端工程开发，不受 dsh 预览版改动和缓存影响；
  - 脱离 dsh 也能在浏览器里用；
  - 换外壳或给其他系统复用不必重写；
  - dsh 升级的影响限制在入口层。
- **代价**：
  - 多一个本地服务要运行和保护（只监听回环、口令、Host 校验）；
  - 主题映射表和消息桥要随 dsh 维护；
  - 过渡期内插件界面和网页并存；
  - 焦点在框内时 dsh 快捷键大概率不生效，需要时经消息桥转发。
- **尚未验证**（S3 遗留，进入阶段 2 时补）：
  - Desktop 退出时本地服务是否随之停止；
  - 嵌入状态下控制台有无错误；
  - 网页工程的技术选型（框架、构建、组件库），以及打包后经本地服务提供的方式。
