# ADR 0007：dsh 锁定版本升到 0.2.1-rc.2

- 状态：已采纳
- 日期：2026-10-18
- 补充：[ADR 0002](0002-dsh-version-and-reference-source.md) 的第 1、3 条（锁定版本与参考分支）。0002 的其余内容不变，升级规则照旧。

## 背景

2026-10-18，DeepSeek Harness Desktop 自动升级到 0.2.1-rc.2 后，左侧栏的灵感台消失。

原因：dsh 加载插件前会检查插件声明的 dsh 版本要求（`packages/boot/app-boot/src/plugin-compatibility.ts`，0.2.0-rc.2 已有，0.2.1-rc.2 加了 `engines.dsh`）。`packages/dsh-plugin/package.json` 的 `peerDependencies` 写的是 `"@deepseek-ai/dsh-tools": "0.2.0-rc.2"`，按 semver 只匹配 0.2.0-rc.2，宿主版本 0.2.1-rc.2 不满足，插件被拒绝加载。

在隔离 `DSH_HOME` 中用 `dsh plugin allow-version @bluemanta/dsh-plugin@0.0.0 --dsh-version 0.2.1-rc.2 --accept-risk` 放行后，左侧栏灵感台、品牌、网页框均正常。这说明插件代码在 0.2.1-rc.2 上能跑，只差版本声明。

npm 上 `next` 指向 0.2.1-rc.2，`latest` 仍是 0.2.0-rc.2；`@deepseek-ai/dsh-tools@0.2.1-rc.2` 已发布。

## 上游变化（0.2.0-rc.2 → 0.2.1-rc.2，只看插件用到的部分）

对照提交 `c1b47e41fc` 与 `d1b9c04067`：

| 插件用到的 | 变化 | 对插件的影响 |
|---|---|---|
| 兼容检查 | 新增 `engines.dsh`：有它时只看它，忽略 peer；否则每个 `@deepseek-ai/dsh` / `@deepseek-ai/dsh-*` 的 peer 都要满足。范围按 semver 判断，预发布版本参与匹配 | 把 peer 改成 0.2.1-rc.2 即可 |
| `defineTool`（`dsh-tools`） | 签名不变；`presentationMeta` 改为嵌套调用也会计算；工具展示模式去掉 `both`；子路径 `./invariant` 删除 | 插件只用 `name`、`description`、`parameters`、`output.schema`、`output.render`、`execute(args, exec)` 和 `exec.signal`、`exec.callId`，都没变 |
| `tool.call.toolview` 插槽（ui-tool） | 删掉 `useToolCallArgumentsPartial` 钩子；每个阶段的 block 新增 `name` 和懒读的 `args`；旧的 `argsRaw` 和结果里的 `call` 字段保留 | 工具卡片读的是 `block.argsRaw` 和 `block.call.argsRaw`，仍可用；没用那个钩子 |
| 右侧栏（ui-sidebar-right） | `openTab` 在替换页签时的定位逻辑调整；隐藏面板的 `aria-hidden` 规则调整 | 服务接口 `openTab`、`focus`、`mounted`、`openTabs`、`registerCloseHandler`、`sidebarRightTabs.register` 不变 |
| 布局（ui-layout） | 新增 `shell.bottom` 插槽；字体变量增加 | 不影响；`main` 插槽不变 |
| 左侧栏（ui-sidebar） | 只改样式和文档 | 不影响；`sidebar.panellist`、`sidebar.brand.*` 不变 |
| 插件用到的 7 个插槽名 | 在新版源码中全部还在 | — |
| Desktop 快捷键（`apps/desktop/src/preload-app.ts`） | 没有改动 | S5 的结论（`iframe[data-html-preview]` 且 `name` 匹配）仍成立 |
| 插件开发指南（`cordis-plugin-development`） | 安装前要补齐展示信息：`locale/en.json`、`locale/zh.json` 的 `meta.title` / `meta.description`，原创图标，并在 `exports` 里导出 `./locale/*.json` 和 `./icon`；新增「`appendPluginRecord()` 只给 dsh 实验包用」的提醒 | 展示信息不影响加载，本次不做，列为后续可选改进 |

## 决定

1. **锁定版本改为 0.2.1-rc.2**，和自动升级后的 Desktop App 一致，不追 alpha。
2. **参考源码改为上游提交 `d1b9c04067`**（`release(dsh): 0.2.1-rc.2`）。标签 `dsh-v0.2.1-rc.2` 指向它的合并提交 `687f282e86`，两者文件内容完全相同。本机参考分支是 `~/Developer/bluemanta-harness` 的 `ref/dsh-0.2.1-rc.2`；`ref/dsh-0.2.0-rc.2` 保留，用于对照旧版。
3. **插件仍用精确版本声明**：`peerDependencies` 和 `devDependencies` 的 `@deepseek-ai/dsh-tools` 都写 `0.2.1-rc.2`，不改用范围，也不加 `engines.dsh`。这样每次升级都要显式核对一遍上游变化，符合 ADR 0002 的升级规则。
4. 产品代码的改动按 ADR 0004 委派给 Cursor：`packages/dsh-plugin` 的依赖版本、`scripts/dev-dsh.mjs` 的 `DSH_PACKAGE` 和版本检查、测试中的版本断言、README 中的版本号，以及根 `package-lock.json`。
5. 合并前用户本机 Desktop 靠 `compatibility.json` 里的版本豁免运行；合并并在隔离 `DSH_HOME` 验收通过后，经用户同意撤掉这条豁免。

## 后果

- Desktop 下次自动升级（例如到 0.2.1-rc.3 或 0.2.1）时，插件会再次被拒绝加载，需要重复本流程。代价是每次升级一条 ADR 和一个小任务；好处是升级前一定会对照上游变化。
- 如果自动升级过于频繁，可以改用范围（例如 `engines.dsh: ">=0.2.1-rc.2 <0.3.0"`），由用户决定后新增 ADR。
- 历史文档（ADR 0001、spikes、阶段计划）里的 0.2.0-rc.2 是当时的验证记录，不改写。
